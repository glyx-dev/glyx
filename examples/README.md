# Glyx Examples

A collection of example desktop apps that demonstrate the Glyx framework end to
end — React/TypeScript UIs driven by a custom Skia/Vello renderer, with real
`@glyx-dev/*` packages and capability-gated system APIs.

These are the same apps showcased on the docs site
([glyx.dev](https://glyx.dev)) under "Built with Glyx".

## Examples

| Example | Mode | Demonstrates |
|---------|------|--------------|
| [`hello-world`](./hello-world) | Native | The minimal app: a `View` + `Text` rendered via `@glyx-dev/react`. Start here. |
| [`calculator`](./calculator) | Native | A basic calculator UI — component composition and state with `@glyx-dev/react`. |
| [`tasks`](./tasks) | JS-only | Persistent to-do manager. `db` (SQLite) CRUD, `@glyx-dev/router`, `@glyx-dev/design`, `@glyx-dev/store`. Zero Rust. |
| [`dashboard`](./dashboard) | JS-only | Analytics dashboard: live `@glyx-dev/charts` (line/area/bar/pie), design system, `fs`/`dialog`/`window`. |
| [`files`](./files) | Native | File explorer + Markdown editor using `@glyx-dev/split-pane`, `@glyx-dev/markdown`, `fs`/`dialog`. |
| [`model-viewer`](./model-viewer) | Native | Interactive 3D scene with `@glyx-dev/three` (geometry, lights, auto-rotate) on the GPU `Canvas3D`. |
| [`log-viewer`](./log-viewer) | JS-only | Log file viewer: `fs`/`dialog` + `@glyx-dev/design` to open and display log files. |
| [`media-player`](./media-player) | JS-only | Audio/video player with `audio`/`video`/`db`/`dialog` capabilities, design system, toasts. |
| [`notes-app`](./notes-app) | Native | Richer demo combining `@glyx-dev/router`, `@glyx-dev/store`, `@glyx-dev/keychain`, `@glyx-dev/three`, `@glyx-dev/drizzle`. |

**Mode legend**
- **Native** — the app ships a `Cargo.toml` + Rust host (`src/main.rs`) and builds
  with the bundled runtime (`dev` feature).
- **JS-only** — the app has only `glyx.config.ts` + JS (no `Cargo.toml`) and runs on
  the prebuilt `glyx-runner`. Requires the runner to be cached first (see below).

## Running an example

Prerequisites: install the Glyx CLI.

1. **JS-only apps only** — build the dev runner once (caches dev + prod runners in
   `~/.glyx/runners/`):

   ```sh
   glyx runtime build
   ```

2. From any example folder, launch it:

   ```sh
   cd examples/<name>
   glyx dev
   ```

   - Native apps compile the Rust host automatically.
   - JS-only apps run on the cached `glyx-runner`.

3. Build a release binary:

   ```sh
   glyx build
   ```

Scaffold a new app with `glyx create <name>`.

## Structure of each example

Every example follows the canonical `glyx create` layout:

- **`glyx.config.ts`** — `name` (canonical id used by the CLI), `version`, `app`
  metadata, `window`, `capabilities`, and `dev` entry/output. `canvas3d` is a
  **build feature**, not a capability.
- **JS/TS entry** — under `js/`, `src/`, or `ui/` (e.g. `app.jsx`), importing
  `@glyx-dev/react` and app packages, wrapped in `<ThemeProvider>`.
- **Native apps** additionally have `Cargo.toml` + `src/main.rs`.
- **`.gitignore`** ignores `js/dist/` (build output) and `node_modules/`.

## Notes

- `app.js` / `js/dist/app.js` are generated by `glyx dev` / `glyx build` — not
  authored or committed.
- Polyfills (`performance`, `setTimeout`, `setInterval`, `MessageChannel`) are
  auto-installed by `@glyx-dev/react`; no hand-written polyfill file is needed.
